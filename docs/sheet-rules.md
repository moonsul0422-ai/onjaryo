# 시트 작성 규칙

시트의 한 줄이 사이트의 자료 한 건이 된다. 이 문서는 그 줄을 어떻게 적는지,
그리고 **왜** 그렇게 적어야 하는지를 다룬다.

새 자료를 넣을 때는 `docs/curation-prompt.md` 를 Claude 에 붙여넣어 줄을 받는다.
이 문서는 그 줄을 시트에 넣기 전후로 사람이 확인하는 것들이다.

---

## 왜 이 문서가 있나

2026년 9월, 시트에 93줄을 넣었는데 사이트에는 41건만 올라왔다. 52줄이 조용히
빠졌고, 원인을 찾는 데 하루가 걸렸다. 빠진 이유는 전부 아래 규칙 중 하나였다.

| 빠진 줄 | 원인 |
|---|---|
| 40줄 | id 에 한글이 들어감 |
| 12줄 | 영역(topics)에 목록 밖 낱말을 씀 |

여기에 더해, 등록은 됐지만 반쪽이 된 줄이 더 있었다 — 열이 한 칸씩 밀린 12줄,
같은 자료가 두 번 들어간 6줄, 목록 페이지를 원문 주소로 넣은 19줄.

---

## 1. 이걸 어기면 그 줄은 아예 안 올라간다

| 칸 | 규칙 | 어기면 |
|---|---|---|
| **id** | 영문 소문자·숫자·하이픈만. 한글·대문자·공백·밑줄 금지 | 줄 전체 제외 |
| **id** | 다른 줄과 겹치지 않게 | 뒤에 나온 줄 제외 |
| **title** | 비우지 않기 | 줄 전체 제외 |
| **summary** | 비우지 않기 | 줄 전체 제외 |
| **sourceUrl** | `http://` 또는 `https://` 로 시작 | 줄 전체 제외 |
| **status** | 비워 두기 (`비공개`·`보류`·`draft` 는 숨김 처리) | 줄 전체 제외 |

### id 를 왜 이렇게까지 따지나

id 가 **그대로 주소가 되기 때문이다.** `jje-260304-k2p` 는 `/r/jje-260304-k2p/` 가 된다.

```
o  jje-260304-k2p            <- 기관코드-YYMMDD-임의3자
o  sen-230426-e4c
o  gwe-52316                 <- 게시글 번호를 써도 된다

x  jje-260304-안전교육자료      <- 한글
x  s-iam-50-수학기초쑥쑥교재     <- 한글
x  GWE-260420-K3T            <- 대문자
x  goe 250110 y4b            <- 공백
```

**id 로 자료를 설명하려 하지 말 것.** 그건 제목이 할 일이다. id 는 짧고 안 겹치면 된다.

**한 번 올라간 id 는 바꾸지 않는다.** 주소가 바뀌면 링크를 공유한 사람, 검색엔진에
쌓인 색인이 전부 깨진다. 아직 안 올라간 줄은 마음대로 고쳐도 된다.

---

## 2. 이건 어겨도 줄은 살지만 반쪽이 된다

| 칸 | 어기면 |
|---|---|
| **topics** | 그 값만 버려짐. 20개 다 틀리면 주제 페이지에서 못 찾음 |
| **subjects** | 그 값만 버려짐. 과목 페이지에서 못 찾음 |
| **grades** | 그 값만 버려짐. 학년 페이지에서 못 찾음 |
| **resourceType** | 비워짐 |
| **license** | `미표기` 로 바뀜 |
| **orgCode** | 기관 표기가 빠짐 |

정해진 값 목록은 `docs/curation-prompt.md` 안에 있다. `npm run prompt` 로 언제든
최신 목록을 다시 뽑을 수 있다. **목록에 없는 낱말은 `tags` 로 보낸다** — tags 는
자유롭게 적어도 되고 검색에도 걸린다.

자주 틀리는 것:

| 이렇게 적으면 | 이렇게 적어야 |
|---|---|
| `실과` / `기술가정` | `실과·기술가정` |
| `통합` / `바슬즐` | `통합교과` |
| `창체` | `창의적 체험활동` |
| `중등` / `고등` | `중학` / `고교` |
| `디지털 사회`, `인공지능` | `디지털·AI` |
| `한글해득`, `문해력`, `기초수학` | `기초학력` (원래 낱말은 tags 로) |
| `e-book`, `전자책` | resourceType 은 `웹콘텐츠·프로그램` |

(앞의 네 줄은 sync 가 알아서 바꿔 준다. 나머지는 사람이 고쳐야 한다.)

## 3. 붙여넣은 직후 확인 4가지

**① 칸이 밀리지 않았나**

가장 찾기 어려운 실수다. 빈 칸 하나가 더 들어가면 그 뒤가 전부 한 칸씩 밀린다.
줄은 등록되지만 과목이 비고, 영역 자리에 교과명이 들어가고, 태그 자리에 라이선스가
들어간다. 경고도 애매하게만 뜬다.

> **보는 법**: `topics` 칸을 본다. `수학`·`국어` 같은 **교과명**이 보이면 밀린 것이다.
> 거기엔 `기초학력`·`안전` 같은 영역이 있어야 한다.

고치는 법: 그 줄의 `subjects` 칸부터 오른쪽 끝까지 잡아서 한 칸 왼쪽으로 당긴다.

**② 이미 있는 자료가 아닌가**

시트에서 `Ctrl+F` 로 원문 주소를 찾아본다. 같은 주소가 이미 있으면 안 넣는다.

id 가 다르면 중복 검사에 안 걸린다. 사이트에 같은 자료가 두 번 나온다.

같은 자료를 여러 기관이 각자 올린 경우에는 **발행한 기관 것을 남긴다.** 이 사이트는
발행 기관 쪽 조회수가 올라가라고 만든 것이라, 재게시한 글을 가리키면 그 목적이 깨진다.

**③ 원문 주소가 그 자료로 바로 가나**

주소를 눌러서 그 자료가 바로 열려야 한다. 게시판 목록이나 검색 결과 주소면 안 된다.

> **보는 법**: 새로 넣은 줄들의 주소가 서로 같으면 목록 페이지다.

**④ 요약과 활용팁을 읽어 봤나**

이 두 칸이 이 사이트의 값어치 전부다. Claude 가 써 준 것을 그대로 두지 말고
직접 읽고 고친다. 원문을 안 열어 보고 제목만으로 지어낸 요약은 티가 난다.

## 4. 올린 뒤 확인

재배포하면 빌드 로그 끝에 이렇게 찍힌다.

```
[sync] 자료 87건 / 기관 24곳 · 경고 12건 (source=sheet)
[sync] 시트 87행 중 87건 등록, 0건 제외
```

- **`source=sheet`** 인지 본다. `seed` 나 `seed-fallback` 이면 시트를 못 읽은 것이다
  (사이트 푸터에도 `예시 데이터` 배지가 뜬다). 실서비스 배포는 이때 아예 실패한다.
- **시트 행 수와 등록 건수가 같은지** 본다. 다르면 그 위의 `!` 경고 줄에 어느 행이
  왜 빠졌는지 행 번호와 함께 적혀 있다.
- **경고 건수**는 0이 아니어도 된다. 값 하나가 버려졌다는 뜻일 뿐이다. 다만 새로
  넣은 줄 때문에 늘었다면 한 번 훑어본다.

---

## 5. 기관을 새로 쓸 때

자료 탭에 새 `orgCode` 를 쓰기 전에 **기관 탭에 먼저 추가한다.** 없는 코드를 쓰면
줄은 등록되지만 기관 이름이 안 나오고 기관 페이지도 안 생긴다.

기관 탭 열: `code`, `name`, `shortName`, `region`, `orgType`, `parent`, `homepage`

교육지원청·연구원처럼 시도교육청 밑에 있는 기관은 `parent` 에 상위 기관 코드를
적는다 (예: 강동송파교육지원청 `sen-gs` 의 parent 는 `sen`).

**자료의 원문 주소와 orgCode 의 기관이 서로 맞는지** 본다. 주소는 경북 사이트인데
orgCode 가 광주면, 둘 중 하나가 틀린 것이다.

---

## 6. 표지 이미지

`coverImage` 에는 **파일 이름만** 적는다. `한글놀이터.jpg` 처럼.
파일은 `public/covers/` 에 둔다. 없으면 기관 색 카드가 대신 그려지므로 비워도 된다.

외부 주소(`https://...`)와 경로(`/`, `\`)는 막아 두었다. 남의 서버 이미지는 그쪽이
파일을 옮기면 깨진다.
